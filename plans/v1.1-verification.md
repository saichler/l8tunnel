## Not verified

1. **`acme.mode: dns01` with custom domains.** The wildcard needs a real DNS
   provider (as in v1). The custom-domain half uses the same HTTP-01
   on-demand path that was verified against Pebble in `http01` mode.
2. **OIDC against a real provider** (Google, GitHub via an OIDC bridge,
   Keycloak). The mock follows the standard (discovery, PKCE, RS256, nonce);
   a real provider also needs `https://auth.<base>/callback` registered.
3. **The inspector UI in a browser.** The page is served and its API is
   tested; its rendering was not checked visually.

## Defects found during v1.1 (fixed)

- An edit to the relay router accidentally removed the access-token route
  (`serveTokenTunnel`); the build caught it and it was restored from the
  previous commit.
- A test expected a TLS 1.3 client-certificate rejection at dial time; in
  TLS 1.3 it arrives on first read. The product behavior was right, the
  test was fixed.
- Real-`ssh -J` smoke runs needed the client options in an `-F` config
  file: `-J` doesn't pass command-line `-o` options to the jump
  connection. No product change.
